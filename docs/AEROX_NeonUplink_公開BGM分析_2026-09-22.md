## 2. 発見された問題（優先度順）

### P1. アーティスト名「AERØX」は検索で機能していない — 最重要

**表記の問題：** `Ø` は日本語・英語どちらのキーボードでも通常入力できない。
実際に **Shazam は「Aerox」（Ø無し）として索引している**。つまりプラットフォーム側で表記が割れている。

**衝突の問題：** その「Aerox」が、極めて混雑した語だった。

| 競合 | 内容 |
|---|---|
| **Yamaha Aerox** | 1997年〜のスクーター。欧州・東南アジア・インドで販売され、Wikipedia 項目もある |
| **Aerox Aviation Oxygen Systems** | 航空用酸素システムの世界大手。1981年〜、`aerox.com` を保有 |
| Aerox Advanced Polymers | 風力タービン用ポリマー企業 |
| Aerox SP | 鎮痛薬の商品名 |

→ 「Aerox」で検索した人が音楽に辿り着く可能性はほぼゼロ。
**Still Frequency と同じ「名前が被っている」問題が、アーティスト名側にも起きている。**

### P2. ジャンルが「Dance」で登録されている

Shazam 上で "Phase Static" は **dance** と分類されている。

DSP のアルゴリズムはジャンルメタデータを使ってプレイリスト候補を絞る。
Chillstep／アンビエント／作業用BGM として作ったものが `Dance` で登録されていると、
**集中・作業・睡眠系のプレイリスト面に乗らない**。意図した聴かれ方と配信設定がずれている。

→ 次回配信時にジャンル・サブジャンルを見直す。既存分も配信代行側で修正できる場合がある。

### P3. 名前が3つに分散している

| 面 | 名前 |
|---|---|
| YouTube チャンネル | Neon Uplink |
| アーティスト名（DSP） | AERØX |
| アルバム名 | Neon Uplink |

YouTube で知った人が DSP で「AERØX」に辿り着けず、逆に DSP で聴いた人が YouTube チャンネルに来られない。
**2つの面がそれぞれ別のブランドとして存在してしまっている。**

Neon Uplink は（Still Frequency と違い）自分のものなので被りの問題はない。
統一するなら **Neon Uplink 側に寄せる**のが自然。P1 の検索衝突も同時に解消する。

### P4. レーベル名「South-South Records」に検索資産がない

同名の実在レーベルは検索で見つからなかった（South Records、Deep South Records 等は別物）。
自己申告の屋号と思われる。それ自体は問題ないが、**発見性への寄与はゼロ**。ここに期待しない。

### P5. 曲名が一般語の組み合わせで、単体では埋もれる

`Signal` `Static` `Current` `Bloom` `Circuit` `Echo` はいずれも他アーティストの曲名と衝突しやすい語。
加えて **「Ghost Current」と「Echo Current」で Current が重複**している。

アルバムとしての統一感はある（語彙圏が揃っている）が、**1曲単位での検索到達は期待できない**。

> 補足：この語彙圏の混雑は実測できている。チャンネル改名候補として出した
> `Static Bloom` は複数バンドと衝突、`Pale Signal` は Spotify に既存アーティストがあった。
> 同じ語彙プールを曲名にも使っている以上、同じ混雑の中にいる。

### P6. フォーマットが需要と合っていない — 戦略上の最重要論点

- **配信している形式**：10曲33分のアルバム
- **YouTube の作業用BGM需要**：1〜3時間の長尺ミックス、または無限ループ

33分のアルバムをそのまま YouTube に上げても、「作業用BGM」「作業用 2時間」で検索する人の意図には応えていない。

**DSP用の楽曲資産と、YouTube用の長尺BGMは別プロダクトとして設計する必要がある。**
同じ音源を素材として使い回すのは正しいが、YouTube 側は尺・構成・サムネ・タイトルを別設計にする。

## 3. 数値について（重要な注意）

検索スニペットは AERØX の Spotify 月間リスナーを「5」と報告した。
**ただしこの数値は信用していない。** 同じ検索セッションで、無関係なアーティスト（Pale Signal）についても
まったく同じ「5 monthly listeners」が返っており、スニペット生成側の既定値である可能性が高い。

**実数は YouTube Studio / Spotify for Artists で直接確認すること。** 本ドキュメントでは数値を前提にした判断をしていない。

## 4. 優先順位の提案

| 順位 | 打ち手 | 理由 |
|---|---|---|
| 1 | **アーティスト名を Neon Uplink 系に統一**（P1 + P3） | 検索衝突の解消とブランド統合が同時に片付く。既存リリースが少ない今が最も安い |
| 2 | **ジャンル登録を Chillstep / Ambient / Electronic 系に修正**（P2） | 配信代行側の設定変更だけで済む可能性があり、費用対効果が最も高い |
| 3 | **YouTube 用に長尺版を別設計**（P6） | 需要の形に合わせる。既存音源を素材として再利用できる |
| 4 | 曲名の命名規則を見直す（P5） | 次回リリースから。既存分は触らなくてよい |

※ 1 を実行する場合、DSP 上のアーティスト名変更は配信代行の手続きが必要で、
既存リリースの紐付けが切れることがある。**リリース数が増える前に決めるほど安い。**

## 5. 次の分析に必要な材料

以下が揃えば、外形ではなく実データの分析に入れる。

### A. YouTube Studio のデータ（最優先）
アナリティクス → 右上の**エクスポート**（↓アイコン）→ **カンマ区切り値(.csv)**。以下の3画面それぞれで実行：

1. **コンテンツ**タブ … 動画別の視聴回数・平均視聴時間・平均視聴率・インプレッションCTR
2. **視聴者**タブ … 再訪問者／新規視聴者、視聴時間帯
3. **リーチ**タブ … トラフィックソース（検索・ブラウジング機能・関連動画の比率）

→ 「どの動画が刺さったか」ではなく**「なぜ刺さったか」**まで踏み込める。

### B. 公開中の動画メタデータ
タイトル・説明文・タグ・サムネの文言を、動画ごとにテキストで。
→ 命名規則・SEO・サムネ文言の一貫性を、上の CSV の数値と突き合わせて分析する。

### C. 音源ファイル
mp3 / wav をアップロード。**解析環境は構築済み**（ffmpeg 7.0.2 + librosa 0.11.0 + pyloudnorm）。
`tools/analyze_audio.py` で以下を一括算出（合成音源で動作確認済み。
ラウドネス測定値は ffmpeg の EBU R128 メーターと 0.1dB 以内で一致することを検証した）：

- ラウドネス（LUFS）とカタログ全体のばらつき ← **連続再生するBGMでは音量差が離脱要因になる**
- 配信基準 −14 LUFS からの乖離（プラットフォーム正規化後に痩せていないか）
- BPM・推定キー・スペクトル重心（明るさ）
- クリッピング検出、ステレオ相関（ヘッドホンでの広がり）

10曲あれば、**カタログとしてマスタリングが揃っているか**を数値で点検できる。
